# 全栈数据分析平台

FastAPI + Pandas + Scikit-learn + ECharts 的一体化数据分析平台：约 11.1 万条记录、6 个业务模块、统一分析层、JSON API，以及支持多轮工具编排（最多 3 次工具调用，无 API Key 时自动降级为规则引擎）的 AI Agent。

在线地址：https://data-platform-vp73.onrender.com

|------|--------|----------|

| 🎮 游戏评论 | 2,531 条 → 清洗后 2,362 条 | VADER 文本情感 vs 用户评分、主题词典、TF-IDF 关键词、平台极化 |

| 🏦 贷款违约 | 5,000 条模拟信贷 | ROC/PR、KS、阈值决策、概率校准、置换重要性、分群违约率 |

## 几个关键结论

- 北京餐饮人均消费为 0 的 13,309 家店是**未采集**而非免费；剔除后有效样本 31,203 家，人均中位数 **¥67**、P90 ¥145（旧口径把 0 元计入，均值被拉低到 ¥60.7）。
- 游戏评论的文本情感与评分只有 **61.1%** 一致；343 条文本正面但评分偏低，说明「玩家嘴上夸、手上打低分」的错位真实存在。
- 留存必须用队列口径：首周流失 **49.1%**，W4 留存 **23.9%**；推荐渠道 W4 留存 30.2%，广告投放仅 19.6%，但广告占注册量 35.5%。
- 贷款模型随机森林 AUC **0.939**、逻辑回归 **0.900**、KS **0.735**；按「好客户赚 2,000 / 坏客户亏 10,000」的成本假设，最优阈值约 **0.25**，而不是默认的 0.5。
- 租房数据里整租中位租金 5,236 元、合租 1,400 元，但面积中位数 88.8㎡ vs 17.5㎡，且同房型内租金与面积几乎不相关（r≈0）——单价随面积下降主要是除法效应，不能解读为小户型溢价。地铁/学校/装修的组间差异均接近 0，不能据此写「地铁房溢价」。
- 招聘数据只有 **50.1%** 是数据相关岗位，其余是销售、质量、结构等关键词噪声；数据分析岗数量最多（760 条）但月薪中位数最低（12,500 元），算法岗 25,000 元。

## 架构

```
data_platform/
├── app.py                  # FastAPI 入口：页面 + JSON API + Agent
├── analysis/               # 纯计算分析层（无 HTML / 无绘图）
│   ├── data.py             # 数据加载缓存 + JSON 序列化
│   ├── food.py
│   ├── game.py
│   ├── retention.py
│   ├── loan.py
│   ├── rental.py
│   └── jobs.py
├── static/
│   ├── app.css             # 设计系统：深色主题 / 响应式
│   ├── common.js           # KPI / 面板 / 表格 / ECharts 封装
│   ├── food.js … jobs.js   # 六个模块的页面脚本
│   ├── agent.js            # 对话交互
│   └── echarts.min.js      # 已内置，离线可用
├── data/
│   ├── beijing_rental.csv  # 35,082 条
│   └── job_data.csv        # 3,523 条
├── bj_food_analysis.xlsx   # 44,512 条
├── Metacriticgames8.csv    # 2,531 条
└── requirements.txt
```

分析层统一暴露 `get_xxx_analysis() -> dict`，页面、JSON API、Agent 复用同一份结果，避免业务口径分叉。

前端不依赖 Vue/React 或构建工具：FastAPI 返回页面骨架，浏览器端 `fetch` JSON API 后用 ECharts 渲染交互图表，首屏与部署都很轻。

## JSON API

| 接口 | 内容 |
|------|------|
| `GET /api/food` | 餐饮价格/菜系/区域/评分/米其林/夜宵/推荐候选 |
| `GET /api/game` | 情感、评分对照、主题、关键词、平台 |
| `GET /api/retention` | 队列矩阵、渠道、设备、流失风险 |
| `GET /api/loan` | ROC/PR、阈值、校准、重要性、分群 |
| `GET /api/rental` | 房型、区域、面积、配套、月度趋势、地图抽样 |
| `GET /api/jobs` | 薪资、城市、经验、学历、公司、岗位族 |
| `POST /api/agent/chat` | `{message, history}` → 多轮工具编排；`params` 支持推荐筛选 |

## 全栈平台的 AI Agent：工具与上下文

全栈数据分析平台的 Agent 不让 LLM 直接算数：LLM 只负责选择工具和组织语言，所有数字都来自 `analysis/*.py` 的 Pandas / Scikit-learn 计算。

- **按字段拆工具**：例如 `loan.thresholds`、`retention.channels`、`rental.rent_types`、`food.recommend`，而不是「每个图表一个工具」。
- **具体餐厅推荐**：全栈平台的 `food.recommend` 支持区域、菜系、价格四类筛选条件：`district / cuisine / min_price / max_price`。默认只在「评分非空 + 评论数 ≥ 50」的 3,310 家店里推荐，避免 1 条评论的 5.0 分；样本不足时依次放宽到 10 条评论、只要评分非空，并在返回里标 `relaxed`。
- **推荐兜底**：用户明确要「推荐一家餐厅」时，如果 LLM 想直接收尾而不调工具，代码会强制先调用一次 `food.recommend`，保证回答落到具体店名、区域、人均、评分和评论数。
- **历史隔离（多轮对话）**：多轮历史只用于理解「它 / 这个 / 再按城市拆一下」这类指代；模块识别以当前问题为准，只有当前问题没提模块时，才继承最近一条带模块的历史，避免前面问过租房、后面每个问题都带租房，导致回答串模块。
- **降级一致**：LLM 失败或未配置 Key 时降级到规则引擎，工具标签和最终回答保持一致；DeepSeek 调用 45 秒超时，失败重试一次。

## 本地运行

```bash
pip install -r requirements.txt
# 方式一：复制 .env.example 为 .env，填入 DEEPSEEK_KEY（推荐，不会被提交）
# 方式二：set DEEPSEEK_KEY=sk-xxx
python app.py
```

不设置 Key 时 Agent 自动使用规则编排，页面与六个 JSON API 不受影响。

访问 http://127.0.0.1:8000

首次运行会自动下载 VADER 情感词典；ECharts 已内置于 `static/`，离线环境无需再拉取前端资源。

## 数据说明

- 餐饮、游戏评论为公开数据集；租房与招聘数据已复制到 `data/`，clone 后可直接运行。
- 留存与贷款为**模拟数据**：生成机制在 `analysis/retention.py`、`analysis/loan.py` 中显式写明，指标可复现（随机种子固定）。
- 租房与招聘数据分布过于均匀/集中，存在合成或抓取偏差，模块内已标注哪些结论不能外推。
